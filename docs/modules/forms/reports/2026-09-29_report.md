# Relatório — forms — 2026-09-29

## Resumo

O módulo de formulários cobre o agregado Form, Section, Question, Option, FormMembership e FormResponse. O criador do formulário entra como owner. A ordem das perguntas é contínua dentro da seção. Respostas JSON ficam criptografadas e só podem ser enviadas quando o formulário está publicado.

## Ambiente

```bash
make up
docker compose exec api alembic upgrade head
docker compose exec api python -m scripts.seed
```

A migração aplicada é `0002_forms`. O banco do projeto já estava no ar; o MCP local deste repositório não estava conectado na sessão, então a estrutura foi conferida pela própria migração e pelos testes.

## Exemplo

Criar formulário:

```json
{ "title": "Pesquisa interna", "description": "Clima" }
```

Publicar:

```json
{ "status": "published" }
```

Responder:

```json
{ "answers": [{ "question_id": "uuid", "value": "Bom" }] }
```

## LGPD

- Form, Section, Question e Option não guardam dado pessoal.
- FormMembership liga um usuário a um formulário e usa soft-delete.
- FormResponse guarda `respondent_id` e o JSON das respostas. O JSON é tratado como dado pessoal e criptografado com Fernet antes de persistir. Não entra em log.
- Formulário também usa soft-delete.
- Email do membro ou do respondente só aparece para owner ou administrador, que já estão autorizados a ver o formulário.

```json

```

A resposta segue o envelope da API, chave `form`.

### LGPD no cliente

- Access token e refresh token ficam em cookies `HttpOnly`, `SameSite=Strict`. Em produção, `Secure`.
- Nada de dado pessoal vai para `localStorage` ou `sessionStorage`.
- CPF só aparece no perfil do próprio usuário, com `autocomplete="off"`.
- E-mail e telefone de outras pessoas aparecem apenas nas telas em que a API já os devolve para owner ou administrador.
- O JSON de respostas não é persistido no navegador.
